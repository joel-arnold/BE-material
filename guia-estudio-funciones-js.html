Bloque 1

Declaración de función

En JS, las funciones son objetos de primera clase (first-class objects): se pueden asignar a variables, pasar como parámetros y retornar desde otras funciones. La diferencia con otros objetos es que pueden ser invocadas.

function sayHi(name) {
  return `Hi ${name}`;
}
  • Palabra clave function, nombre, parámetros entre (), cuerpo entre {}.
  • return es opcional. Sin él, la función devuelve undefined.

Parámetros

Los parámetros pueden tener valores por defecto. Si no se pasan, su valor es el default o undefined. Se pueden pasar de más (los extras se ignoran) y el orden importa.

'use strict';

function sayHi(name, greeting = 'Hi') {
  return `${greeting} ${name}`;
}

console.log(sayHi('John', 'Hello')); // Hello John
console.log(sayHi('John'));          // Hi John  ← usa el default
console.log(sayHi());                 // Hi undefined
console.log(sayHi('Hello', 'John')); // John Hello ← orden importa
console.log(sayHi('John', 'Hello', '!')); // Hello John ← el extra se ignora
Importante
JS no lanza error si llamás la función con más o menos parámetros de los definidos. Esto sorprende a los que vienen de Java o C. Es una fuente frecuente de bugs silenciosos.
Bloque 2

Expresión de función

Una expresión de función crea una función y la asigna a una variable. El nombre de la función es opcional; si existe, solo es accesible dentro del cuerpo de la función (útil para recursividad).

'use strict';

// con nombre (el nombre 'sayHi' solo existe adentro)
const greet = function sayHi(name, greeting = 'Hi') {
  return `${greeting} ${name}`;
};

// anónima
const anonymousGreet = function(name, greeting = 'Hi') {
  return `${greeting} ${name}`;
};

console.log(greet('Jane', 'Hello'));          // Hello Jane
console.log(anonymousGreet('Josh', 'Hello')); // Hello Josh
// sayHi('Jane', 'Hello'); ← ReferenceError: sayHi is not defined
Bloque 2 (cont.)

Hoisting

Las declaraciones de función son hoisted: JS las mueve al inicio del scope, así que podés llamarlas antes de declararlas en el código. Las expresiones de función (y las arrow functions) no son hoisted.

'use strict';

hoisting('esto funciona'); // ✅ se puede llamar antes de declararla
// noHoisting('esto falla'); ← ReferenceError

function hoisting(text) {
  console.log(text);
}

const noHoisting = function(text) {
  console.log(text);
};
Importante
Aunque el hoisting permite llamar funciones antes de declararlas, no significa que sea buena práctica. En proyectos reales siempre conviene declarar antes de usar.
Bloque 3

Scope

Cada función crea su propio scope. Las variables declaradas dentro:

  • Ocultan a las del mismo nombre del scope exterior (dentro de la función).
  • No existen fuera de la función.

Las variables del scope externo sí son accesibles desde dentro, si no hay una local con el mismo nombre.

'use strict';

let x = 1;
let y = 'test';

withVars();

function withVars() {
  let x = 'a'; // oculta la x de afuera, solo acá adentro
  console.log(x, y); // a test
}

console.log(x, y); // 1 test  ← la x de afuera no cambió
Bloque 4

Arrow functions

Sintaxis más concisa para expresiones de función. Muy usadas en JS moderno y en Node.js.

Sintaxis

// forma mínima: una sola expresión, sin llaves ni return
const sayHi = (name, greeting = 'Hi') => `${greeting} ${name}`;

// con bloque: necesita return explícito
const greet = (recipient, greeting = 'Hi') => {
  if (typeof recipient === 'string') {
    return `${greeting} ${recipient}`;
  }
  if (typeof recipient === 'object') {
    return greet(`${recipient.firstName} ${recipient.lastName}`, greeting);
  }
};

console.log(sayHi('John', 'Hello'));                         // Hello John
console.log(greet({ firstName: 'Jane', lastName: 'Doe' }, 'Hello')); // Hello Jane Doe

Restricciones importantes

⚠ Diferencia crítica con funciones normales
Las arrow functions no tienen su propio this. Heredan el this del contexto donde fueron creadas (lexical this). Por eso no deben usarse como métodos de objetos ni como constructores. Esto va a ser muy relevante cuando veamos objetos y clases la clase que viene.
Característica Declaration Expression Arrow
Hoisting ✓ Sí ✗ No ✗ No
this propio ✓ Sí ✓ Sí ✗ No (lexical)
Usable como constructor ✓ Sí ✓ Sí ✗ No
Puede ser anónima ✗ No ✓ Sí ✓ Siempre
Bloque 5

Funciones de orden superior (higher-order functions)

Una función de orden superior es una función que recibe otra función como parámetro y/o devuelve una función como resultado. Son uno de los patrones más importantes en JS — la propia API del lenguaje las usa constantemente.

Función como parámetro — forEach

El ejemplo más directo: forEach recibe una función y la ejecuta por cada elemento del array, pasándole (valor, índice, array).

'use strict';

const words = ['Hi all', 'this are', 'high-order functions'];

words.forEach((value, index) =>
  console.log(`Item ${index + 1}: '${value}'`)
);
Salida
Item 1: 'Hi all'
Item 2: 'this are'
Item 3: 'high-order functions'

Función como valor de retorno (closure)

Una función puede devolver otra función. La función retornada "recuerda" las variables del scope donde fue creada — a esto se lo llama closure.

'use strict';

function makeGreeter(greeting) {
  return (name) => `${greeting} ${name}!`; // recuerda 'greeting'
}

const sayHello = makeGreeter('Hello');
const sayHola  = makeGreeter('Hola');

console.log(sayHello('Jane')); // Hello Jane!
console.log(sayHola('Juan'));  // Hola Juan!
Bloque 6

Callbacks

Un callback es una función que se pasa como argumento a otra función para ser ejecutada más tarde — generalmente al finalizar una tarea. Es el primer mecanismo que usa JS para manejar código asincrónico (luego vienen Promises y async/await).

function doSomething(callback) {
  console.log('Haciendo algo...');
  callback(); // ejecuta la función que recibió
}

function sayHello() {
  console.log('¡Hola!');
}

doSomething(sayHello);
// Haciendo algo...
// ¡Hola!

Ponete a prueba

Respondé cada pregunta mentalmente y después tocá para revelar la respuesta y verificar.

1. Respecto al hoisting, ¿qué diferencia hay entre una function declaration y una function expression?
Las declarations se hoistean: podés llamarlas antes de declararlas en el código. Las expressions (y las arrow functions) no: usarlas antes de la línea donde se definen lanza un ReferenceError.
2. ¿Qué imprime?
saludar();
function saludar() { console.log('hola'); }
Imprime hola. Es una function declaration, así que está disponible aunque la llames antes de declararla (hoisting). Si fuera una expression asignada a const/let, daría error.
3. ¿Por qué no conviene usar una arrow function como método de un objeto?
Porque las arrow functions no tienen su propio this: lo heredan del contexto donde se crean. Como método, this no apuntaría al objeto y no podrías acceder a sus propiedades. Para métodos: shorthand o function.
4. ¿Qué es una higher-order function? Dá un ejemplo.
Una función que recibe otra función como parámetro y/o devuelve una función. Ejemplos: forEach, map, filter (reciben un callback). Una función que devuelve otra función también lo es.
5. ¿Qué es un closure?
Una función que recuerda las variables del scope donde fue creada, aunque ese scope ya haya terminado de ejecutarse. Es lo que permite que una función devuelta por otra siga accediendo a los parámetros de la función externa.
6. ¿Qué imprime? ['a','b'].forEach((v, i) => console.log(i, v));
Imprime 0 a y 1 b. forEach le pasa al callback el valor, el índice y el array (en ese orden); acá usamos los dos primeros.
