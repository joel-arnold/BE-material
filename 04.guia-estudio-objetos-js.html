Bloque 1

Qué son los objetos

Un objeto en JS es un tipo de dato que permite agrupar datos y comportamiento en una sola entidad. Los datos se llaman propiedades y el comportamiento, métodos (que son funciones). Las propiedades son pares clave-valor: la clave es un string único dentro del objeto, y el valor puede ser cualquier cosa válida en JS — incluido otro objeto o un array.

const person = {
  firstName: 'Ada',
  lastName: 'Lovelace',
  age: 36,
  hobbies: ['matemática', 'programación'], // un array
  address: {                              // un objeto anidado
    street: 'Calle 123',
    city: 'Londres',
    country: 'Inglaterra',
  },
};

Acceder a las propiedades: punto vs corchete

Hay dos notaciones. La de punto es la habitual. La de corchete es necesaria cuando la clave tiene caracteres no válidos para un identificador (espacios, guiones) o cuando la clave es dinámica (está en una variable).

// notación punto
console.log(person.firstName);            // Ada
console.log(person.address.city);         // Londres (anidado)

// notación corchete — la clave es un string
console.log(person['firstName']);         // Ada

// imprescindible cuando la clave es dinámica
const campo = 'age';
console.log(person[campo]);              // 36

Agregar, modificar y borrar

Los objetos son dinámicos: se pueden agregar y quitar propiedades después de crearlos.

person.job = 'matemática';   // agregar una propiedad nueva
person.age = 37;             // modificar una existente
delete person.job;           // borrar una propiedad

// ¿existe la propiedad?
console.log('age' in person);   // true
console.log('job' in person);   // false

Acceso seguro a propiedades anidadas: optional chaining

Si intento acceder a una propiedad de algo que no existe, JS lanza un error. El operador ?. (optional chaining, ES2020) devuelve undefined en vez de romper.

// ❌ si 'contact' no existe, esto LANZA un error
// console.log(person.contact.email);  → TypeError

// ✅ optional chaining: devuelve undefined sin romper
console.log(person.contact?.email);   // undefined
console.log(person.address?.city);    // Londres
Conecta con la clase de sintaxis
Recordá que los objetos son un tipo no primitivo: se pasan y se asignan por referencia. Dos consecuencias: const no congela el contenido (podés modificar propiedades de un objeto const, solo no reasignarlo); y dos objetos distintos nunca son iguales aunque tengan el mismo contenido — {a:1} === {a:1} es false, porque se comparan las referencias, no los valores.
Bloque 2

Métodos y this

Un método es una función guardada como propiedad de un objeto. Se invoca con la clave seguida de (). Hay dos formas de definirlos: la sintaxis shorthand (recomendada) y la forma con function.

Shorthand (recomendada)

greet() {
  return 'Hola';
}

Con function (equivalente)

greet: function() {
  return 'Hola';
}

this: el objeto sobre el que se llama el método

Dentro de un método, la palabra clave this apunta al objeto sobre el que se invocó el método. Es lo que permite que el método acceda a las otras propiedades del objeto.

const person = {
  firstName: 'Ada',
  lastName: 'Lovelace',
  greet() {
    return `Hola, soy ${this.firstName} ${this.lastName}`;
  },
};

console.log(person.greet()); // Hola, soy Ada Lovelace
⚠ Conecta con la clase de funciones
Acá se ve por qué no se usan arrow functions como métodos. Las arrow functions no tienen su propio this — lo heredan del contexto exterior. Si greet fuera una arrow function, this.firstName no apuntaría a person y daría undefined (o un error). Para métodos: siempre shorthand o function, nunca arrow. 
const person = {
  firstName: 'Ada',
  greetMal: () => `Hola, soy ${this.firstName}`, // ❌ arrow
  greetBien() { return `Hola, soy ${this.firstName}`; }, // ✅ shorthand
};

console.log(person.greetMal());  // Hola, soy undefined
console.log(person.greetBien()); // Hola, soy Ada
Bloque 3

Recorrer y copiar objetos

A diferencia de los arrays, los objetos no tienen índice ni length. Para recorrer sus propiedades, lo más común y seguro hoy es usar los métodos de Object:

const person = { firstName: 'Ada', age: 36, city: 'Londres' };

Object.keys(person);    // ['firstName', 'age', 'city']  → las claves
Object.values(person);  // ['Ada', 36, 'Londres']        → los valores
Object.entries(person); // [['firstName','Ada'], ['age',36], ...] → pares

// recorrer clave y valor con for...of + entries
for (const [clave, valor] of Object.entries(person)) {
  console.log(`${clave}: ${valor}`);
}

Copiar un objeto: el operador spread

Como los objetos se pasan por referencia, asignar uno a otra variable no lo copia — ambas variables apuntan al mismo objeto. Para hacer una copia (superficial) se usa el operador spread ...:

const original = { a: 1, b: 2 };

const referencia = original;        // ❌ NO copia: misma referencia
const copia = { ...original };       // ✅ copia superficial (shallow)

copia.a = 99;
console.log(original.a); // 1 — la copia es independiente

// spread también sirve para combinar objetos
const combinado = { ...original, c: 3 }; // { a:1, b:2, c:3 }
Ojo: copia superficial
El spread copia un solo nivel. Si el objeto tiene objetos anidados, esos siguen compartiéndose por referencia. Para una copia profunda existe structuredClone(objeto).
Bloque 4

Prototipos y prototype chain

Hasta acá creamos objetos, les pusimos propiedades y métodos... pero nunca definimos una clase. ¿No se supone que los objetos salen de una clase? En JS, no necesariamente.

JS no usa clases como mecanismo base, sino prototipos: cada objeto tiene una referencia a otro objeto llamado su prototipo, del cual hereda propiedades y métodos. Y ese prototipo tiene a su vez su propio prototipo, formando una cadena de prototipos (prototype chain).

Cómo funciona la búsqueda

Cuando pedís una propiedad o método de un objeto, JS la busca así:

  1. La busca en el propio objeto. Si está, la usa.
  2. Si no está, la busca en su prototipo.
  3. Si tampoco, sigue subiendo por la cadena, prototipo tras prototipo.
  4. Termina al encontrarla, o al llegar a null (donde devuelve undefined).

Todo objeto literal hereda por defecto de Object.prototype — de ahí salen métodos como toString() o hasOwnProperty() que ningún objeto define pero todos tienen.

person
su prototipo→
Object.prototype
su prototipo→
null

Cadena de prototipos de un objeto literal. Object.prototype es el final útil de la cadena; su prototipo es null.

__proto__ vs prototype — la confusión clásica

Son dos cosas distintas que conviene separar bien:

PropiedadQuién la tieneQué es
__proto__Todos los objetosEl prototipo real de ese objeto (de quién hereda).
prototypeSolo las funciones y clasesEl objeto que se usará como prototipo de las instancias creadas con new.
Forma correcta de acceder al prototipo
__proto__ es una propiedad heredada y considerada legada. La forma recomendada por el estándar para leer y escribir el prototipo es Object.getPrototypeOf(obj) y Object.setPrototypeOf(obj, proto). (En esta clase usamos __proto__ en algún ejemplo solo porque es más corto de leer.) Cambiar el prototipo de un objeto ya creado, además, perjudica el rendimiento: no es buena práctica.
Bloque 5

Formas de construir objetos

Escribir cada objeto entero (literal) es cómodo para casos únicos, pero tedioso y propenso a errores si necesitás crear muchos objetos con la misma forma. Por eso existen varias maneras de construir objetos a partir de una definición.

1. Object Factory (función fábrica)

La forma más simple: una función común que arma el objeto y lo devuelve. No usa new ni prototipos especiales.

function createPerson(firstName, lastName, age) {
  return {
    firstName,            // shorthand de firstName: firstName
    lastName,
    age,
    greet() {
      return `Hola, soy ${this.firstName}`;
    },
  };
}

const sam = createPerson('Sam', 'Clemens', 25);
console.log(sam.greet()); // Hola, soy Sam

2. Constructor Function (forma histórica)

Antes de ES6 era la forma estándar de crear objetos a partir de una plantilla. Es una función (por convención, con mayúscula inicial) que se invoca con new. El operador new hace varias cosas por detrás: crea un objeto vacío, le asigna como prototipo el Person.prototype, ejecuta la función con this apuntando a ese objeto nuevo, y lo devuelve. Los métodos compartidos se ponen en .prototype.

function Person(firstName, lastName, age) {
  this.firstName = firstName;
  this.lastName = lastName;
  this.age = age;
}

Person.prototype.greet = function() {
  return `Hola, soy ${this.firstName}`;
};

const sam = new Person('Sam', 'Clemens', 25);
console.log(sam.greet()); // Hola, soy Sam
El error más común con constructor functions
El prototipo del objeto creado (sam) no es la función Person, sino Person.prototype. Tiene sentido: sam es un objeto, debe heredar de un objeto, no de una función. Por eso Object.getPrototypeOf(sam) === Person.prototype es true, pero === Person es false.

3. Class (la forma moderna, desde ES6)

La sintaxis de class hace exactamente lo mismo que las constructor functions, pero de forma mucho más clara. Es azúcar sintáctico: por debajo sigue habiendo prototipos. (Igual que async/await era azúcar sobre promesas — el mismo patrón se repite en JS.)

class Person {
  constructor(firstName, lastName, age) {
    this.firstName = firstName;
    this.lastName = lastName;
    this.age = age;
  }

  greet() {
    return `Hola, soy ${this.firstName}`;
  }
}

const sam = new Person('Sam', 'Clemens', 25);
console.log(sam.greet()); // Hola, soy Sam

Herencia: el contraste que justifica class

Acá se ve por qué class reemplazó a las constructor functions. Heredar con constructor functions requiere tres pasos manuales fáciles de olvidar:

Con constructor function

function Author(fn, ln, age, quote) {
  Person.call(this, fn, ln, age);
  this.quote = quote;
}
// enganchar prototipos a mano
Author.prototype =
  Object.create(Person.prototype);
// restaurar el constructor
Author.prototype.constructor = Author;

Con class

class Author extends Person {
  constructor(fn, ln, age, quote) {
    super(fn, ln, age);
    this.quote = quote;
  }
}

El resultado es idéntico, pero class + extends + super() oculta toda la complejidad de la cadena de prototipos. Así queda esa cadena al heredar:

Si mark no tiene una propiedad, JS la busca subiendo: Author → Person → Object.

Object.create — para profundizar

Es la forma de más bajo nivel: crea un objeto especificando explícitamente cuál será su prototipo, sin new ni funciones de por medio. Sirve para ver la herencia prototípica de forma directa.

const base = {
  saludar() {
    return `Hola, soy ${this.nombre}`;
  },
};

const ada = Object.create(base); // el prototipo de ada es "base"
ada.nombre = 'Ada';
console.log(ada.saludar()); // Hola, soy Ada — saludar viene del prototipo

Con Object.create definimos el prototipo a mano: ada hereda saludar de base, que a su vez hereda de Object.prototype.

Bloque 6

JSON

JSON (JavaScript Object Notation) es un formato de texto para representar datos, basado en la sintaxis de los objetos literales de JS. Aunque nació de JS, hoy es el estándar de facto para intercambiar datos en la web entre cualquier lenguaje y servicio.

Lo central: JSON es un string. JS provee el objeto global JSON con dos métodos para convertir entre texto JSON y objetos JS.

JSON.stringify — serializar

// objeto JS → string JSON
const texto =
  JSON.stringify(person);

JSON.parse — deserializar

// string JSON → objeto JS
const obj =
  JSON.parse(texto);
const person = { firstName: 'Ada', age: 36, hobbies: ['mate', 'código'] };

const texto = JSON.stringify(person);
console.log(texto);
// {"firstName":"Ada","age":36,"hobbies":["mate","código"]}

// con indentación, para que sea legible (3er argumento = espacios)
console.log(JSON.stringify(person, null, 2));

const obj = JSON.parse(texto);
console.log(obj.firstName); // Ada — ya es un objeto JS de nuevo

Las reglas del formato JSON

  • Solo contiene datos, no métodos (no hay funciones en JSON).
  • Las claves y los strings van siempre con comillas dobles. Las comillas simples son inválidas.
  • Los valores pueden ser: string, number, boolean, null, array u objeto.
  • No se permiten comas finales (trailing commas) ni comentarios.

Un ejemplo de JSON válido:

{
  "firstName": "Sam",
  "lastName": "Clemens",
  "age": 74,
  "job": "writer",
  "hobbies": ["escribir", "viajar"],
  "alias": {
    "firstName": "Mark",
    "lastName": "Twain"
  },
  "deceased": true
}
JSON.parse puede fallar — manejá el error
Si el string no es JSON válido (una coma de más, comillas simples, una clave sin comillas), JSON.parse lanza una excepción. Por eso conviene envolverlo en try/catch: 
try {
  const data = JSON.parse(textoRecibido);
} catch (error) {
  console.error('JSON inválido:', error.message);
}
Conecta con la clase de asincronía (y lo que viene)
Esto es exactamente lo que pasa cuando pedís datos a una API: fetch te devuelve texto, y response.json() hace el JSON.parse por vos. En la próxima unidad de APIs vamos a usar JSON todo el tiempo para intercambiar datos entre el frontend y el backend, transformándolo a objetos JS cuando haga falta.
Autoevaluación

Ponete a prueba

Respondé cada pregunta mentalmente y después tocá para revelar la respuesta y verificar.

1. ¿Cuándo es obligatorio usar la notación de corchetes en vez de punto?
Cuando la clave no es un identificador válido (espacios, guiones, empieza con número) o cuando la clave es dinámica (está guardada en una variable). En el resto de los casos, punto.
2. ¿Qué imprime { a: 1 } === { a: 1 }?
false. Los objetos se comparan por referencia, no por contenido: son dos objetos distintos en memoria aunque tengan las mismas propiedades.
3. ¿A qué apunta this dentro de un método?
Al objeto sobre el que se invocó el método. Por eso permite acceder a las demás propiedades del objeto. Y por eso una arrow function no sirve como método: no tiene this propio.
4. ¿Cómo recorrés las claves de un objeto? ¿Y cómo lo copiás?
Para recorrer: Object.keys(), Object.values() o Object.entries(). Para copiar (superficial): spread, const copia = {...original}. Para copia profunda, structuredClone().
5. ¿Qué es la prototype chain y en qué termina?
Es la cadena de prototipos por la que JS busca una propiedad: primero en el objeto, después en su prototipo, y así subiendo. Termina en Object.prototype, cuyo prototipo es null.
6. ¿Cuál es la diferencia entre __proto__ y prototype?
__proto__ lo tienen todos los objetos: es su prototipo real (de quién heredan). prototype existe solo en funciones y clases: es el objeto que se usará como prototipo de las instancias creadas con new.
7. ¿Qué hacen JSON.stringify y JSON.parse, y por qué conviene envolver el parse en try/catch?
stringify serializa: objeto JS → string JSON. parse deserializa: string JSON → objeto JS. parse lanza una excepción si el JSON es inválido (una coma de más, comillas simples), así que se envuelve en try/catch para manejar el error.
Cierre

Resumen de la clase

Puntos clave para recordar

  • Un objeto agrupa datos (propiedades) y comportamiento (métodos) en pares clave-valor.
  • Se accede con notación punto o corchete; el corchete es necesario para claves dinámicas.
  • Los objetos se pasan por referencia: const no los congela, y se comparan por referencia, no por contenido.
  • this en un método apunta al objeto sobre el que se invocó — por eso las arrow functions no sirven como métodos.
  • Para recorrer: Object.keys() / values() / entries(). Para copiar: spread {...obj} (superficial).
  • JS hereda por prototipos: cada objeto hereda de otro objeto, formando una cadena que termina en null.
  • __proto__ es el prototipo de cualquier objeto; prototype existe solo en funciones/clases.
  • Para construir objetos: literal, factory, constructor function (histórica) y class (moderna, recomendada).
  • JSON es texto: JSON.stringify serializa y JSON.parse deserializa (y puede fallar → try/catch).
