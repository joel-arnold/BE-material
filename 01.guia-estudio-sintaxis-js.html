Bloque 1

Variables y constantes

JS tiene tres formas de declarar variables. En código moderno (Node.js, ES6+) se usan let y const. var existe por compatibilidad histórica y no debe usarse en código nuevo.

Palabra claveScopeReasignableHoistingUsar en
letBloque {}✓ SíNo inicializadoVariables que cambian
constBloque {}✗ NoNo inicializadoSiempre que se pueda
varFunción / global✓ SíCon undefinedSolo código legacy

let — variable de bloque

let a;              // declaración sin valor → undefined
let b = 'see ya...';

a = 'hello world';
console.log(a); // hello world
console.log(b); // see ya...

b = '...later';   // reasignación válida
console.log(b); // ...later

const — referencia constante

const impide la reasignación de la variable, pero no congela el contenido del objeto al que apunta. Este punto suele sorprender a los que vienen de otros lenguajes.

✗ Esto falla

const a = 'hello';
a = 'bye'; // TypeError!

✓ Esto funciona

const obj = { name: 'John' };
obj.name = 'John Doe'; // OK
// obj = {...}; → TypeError!
Importante
const no hace que el objeto sea inmutable. Solo evita que la variable apunte a otro objeto. Las propiedades internas del objeto se pueden modificar libremente. La regla práctica: usar const siempre que sea posible, let cuando necesitás reasignar.

var — por qué no usarlo

Tres razones concretas para evitarlo en código nuevo:

  • Scope de función o global, no de bloque: una variable var declarada dentro de un if o un for existe fuera de ese bloque.
  • Hoisting con undefined: se puede usar antes de declararla sin error, devuelve undefined silenciosamente.
  • Se puede re-declarar sin error: var x = 1; var x = 2; es válido, lo que enmascara bugs.

Tipos de datos

JS es de tipado dinámico y débilmente tipado: las variables no tienen tipo, los valores sí. Una misma variable puede contener distintos tipos a lo largo del programa.

let myVariable = 42;    // number
myVariable     = 'bar'; // string
myVariable     = true;  // boolean

Bug histórico de JS
typeof null devuelve 'object', pero null es un tipo primitivo. Es un error de los primeros días del lenguaje que no se puede corregir por compatibilidad. Tenerlo en mente al comparar valores.

Tipos no primitivos

Los tipos no primitivos son Object y Function. La diferencia práctica más importante: los primitivos se pasan por valor, los no primitivos se pasan por referencia. Esto se verá con más detalle en la clase de objetos.

Bloque 2

Arrays

En JS los arrays no son una estructura primitiva sino un objeto Array. Diferencias clave respecto a otros lenguajes:

  • Pueden mezclar tipos en el mismo array.
  • Son de tamaño dinámico — no se declara el tamaño.
  • Acceder a una posición fuera del límite no lanza error, devuelve undefined.
  • Pueden tener posiciones vacías (sparse arrays).
  • Comienzan en índice 0.
let array = [1, true, 'story']; // tipos mezclados

console.log(array[0]);       // 1         ← acceso por índice
console.log(array.at(1));    // true      ← método at()
console.log(array.at(-1));   // 'story'   ← índice negativo = desde el final
console.log(array.length);   // 3
console.log(array[10]);      // undefined ← no lanza error

array[5] = 'last';
console.log(array); // [1, true, 'story', vacío×2, 'last']

Bloque 3

Control de flujo: if / switch

if…else

La sintaxis es idéntica a Java o C. Lo que cambia en JS es que la condición no tiene que ser un booleano: cualquier valor se evalúa como truthy o falsy.

Concepto clave: truthy y falsy
Son falsy: false, 0, '' (string vacío), null, undefined, NaN. Todo lo demás es truthy, incluyendo [] (array vacío) y {} (objeto vacío). 
let a = 1 + 2; // a = 3
let b;         // b = undefined

if (a > 3) {
  console.log('a>3 es verdadero');
} else {
  console.log('a>3 es falso');     // ← se ejecuta esto
}

if (a) {
  console.log('a es truthy');      // ← 3 es truthy, se ejecuta
}

if (b) {
  console.log('b es truthy');
} else {
  console.log('b es falsy');       // ← undefined es falsy
}

Operadores de comparación

El punto más importante para remarcar: igualdad estricta vs no estricta.

console.log(1 ==  '1'); // true  ← convierte tipos antes de comparar
console.log(1 === '1'); // false ← compara tipo Y valor

console.log(1 !=  '1'); // false
console.log(1 !== '1'); // true
Regla de oro
Usar siempre === y !==. El == con conversión implícita de tipos genera comportamientos difíciles de predecir y bugs silenciosos. La única excepción habitual: x == null para chequear tanto null como undefined en una sola condición.

switch

El switch compara con igualdad estricta (===) internamente. No olvidar el break en cada caso: sin él, la ejecución "cae" al siguiente bloque (fallthrough).

let a = '1'; // string

switch (a) {
  case 1:     // number 1 → no coincide (distinto tipo)
    console.log('a es el número 1');
    break;
  case '1':  // string '1' → coincide
    console.log("a es el string '1'"); // ← se ejecuta esto
    break;
  default:
    console.log('sin coincidencia');
    break;
}
Bloque 4

Bucles

La sintaxis de while, do…while y for en JS es prácticamente idéntica a Java y C. El foco acá es en las diferencias.

let i = 0;

// while: evalúa la condición ANTES de ejecutar
while (i < 3) {
  console.log(`i es ${i}`);
  i++;
}

// do...while: ejecuta AL MENOS UNA VEZ, evalúa condición al final
let j = 0;
do {
  console.log(`j es ${j}, condición falsa pero ejecutó una vez`);
} while (j < 0); // condición falsa desde el inicio

// for: inicialización, condición y expresión final en una línea
for (let k = 0; k < 3; k++) {
  console.log(`k es ${k}`);
}
Bloque 5

Iteraciones sobre arrays: for vs forEach

Para iterar sobre arrays hay dos opciones principales. for es una sentencia; forEach es un método del objeto Array que recibe una función.

const datos = ['array', 1, true, undefined, 'story'];

// con for clásico
for (let i = 0; i < datos.length; i++) {
  console.log(`elemento ${i}: ${datos[i]} (tipo: ${typeof datos[i]})`);
}

// con forEach — recibe (elemento, índice, array)
datos.forEach((element, i) => {
  console.log(`elemento ${i}: ${element} (tipo: ${typeof element})`);
});
Salida (idéntica para ambos)
elemento 0: array (tipo: string)
elemento 1: 1 (tipo: number)
elemento 2: true (tipo: boolean)
elemento 3: undefined (tipo: undefined)
elemento 4: story (tipo: string)

¿Cuándo usar cada uno?

forforEach
Necesito el índice✓✓ (segundo parámetro)
Quiero salir antes (break)✓✗ No soporta break
Código más declarativo / moderno✓
Iterar con async/await✓✗ No funciona bien
Lo que sigue
forEach recibe una función como parámetro — eso se llama higher-order function y es uno de los patrones más importantes de JS. Lo profundizamos en la clase de funciones. Por ahora alcanza con saber usarlo.

Ponete a prueba

Respondé cada pregunta mentalmente y después tocá para revelar la respuesta y verificar.

1. ¿Cuál es la diferencia principal entre let, const y var, y cuál conviene usar por defecto?
let y const tienen scope de bloque; var tiene scope de función o global y se hoistea con undefined, por eso se evita. const no se puede reasignar; let sí. Regla práctica: usá const por defecto y let solo cuando necesites reasignar. var, únicamente en código viejo.
2. ¿Qué imprime? const obj = { n: 1 }; obj.n = 2; console.log(obj.n);
Imprime 2. const impide reasignar la variable (apuntarla a otro objeto), pero no congela el contenido: modificar las propiedades del objeto es válido.
3. ¿Qué devuelven 1 == '1' y 1 === '1'? ¿Por qué?
1 == '1' da true (el == convierte tipos antes de comparar). 1 === '1' da false (el === compara valor Y tipo). Conviene usar siempre === y !==.
4. De estos valores, ¿cuáles son falsy?: 0, '', [], null, '0', undefined
Son falsy 0, '' (string vacío), null y undefined. En cambio [] (array vacío) y '0' (string con un cero) son truthy. Solo hay seis valores falsy: false, 0, '', null, undefined y NaN.
5. En un array de 3 elementos, ¿qué pasa si accedo a la posición 10?
Devuelve undefined; no lanza error. Los arrays en JS no avisan cuando accedés fuera de rango.
6. ¿Por qué forEach no sirve si necesito cortar la iteración o usar await?
forEach no soporta break/continue y no espera a los await dentro del callback. Para cortar antes de tiempo o para iteración asincrónica secuencial, conviene un for clásico o for...of.

Resumen de la clase

Puntos clave para recordar

  • Usar const por defecto, let cuando necesitás reasignar. Nunca var en código nuevo.
  • const impide reasignación, no hace inmutable el contenido del objeto.
  • JS es de tipado dinámico: las variables no tienen tipo, los valores sí.
  • typeof null === 'object' es un bug histórico — null es primitivo.
  • Los arrays son objetos: tamaño dinámico, tipos mezclados, sin error por fuera de límite.
  • Siempre usar === y !== (comparación estricta).
  • En if, cualquier valor es truthy o falsy — no tiene que ser booleano.
  • forEach no soporta break ni async/await; para esos casos usar for.
